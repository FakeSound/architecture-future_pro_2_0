# Технический радар — Будущее 2.0

Четыре кольца: **Adopt** — берём в работу, **Trial** — активно пробуем, **Assess** — изучаем, **Hold** — не развиваем.

---

## Платформы и инфраструктура

| Технология                  | Кольцо     | Обоснование                                                                       |
|-----------------------------|------------|-----------------------------------------------------------------------------------|
| Apache Kafka                | **Adopt**  | Центральная событийная шина. Базовое решение для всей межсервисной интеграции     |
| PostgreSQL                  | **Adopt**  | Операционная БД для всех доменов. Database-per-domain                             |
| Kubernetes                  | **Adopt**  | Оркестрация контейнеров. Основа для деплоя всех сервисов                          |
| Kong — API Gateway          | **Adopt**  | Единая точка входа, rate limiting, маршрутизация                                  |
| Keycloak — IAM              | **Adopt**  | SSO и управление доступом для всех доменов                                        |
| Yandex Cloud                | **Adopt**  | Основная облачная платформа на горизонте 3 лет                                    |
| Apache Flink                | **Trial**  | Stream processing для near-real-time витрин. Активно внедряется                   |
| Delta Lake / Apache Iceberg | **Trial**  | Data Lakehouse вместо SQL Server DWH. В процессе внедрения                        |
| Confluent Schema Registry   | **Trial**  | Контрактная валидация событий. Вводится вместе с Kafka                            |
| DataHub                     | **Trial**  | Data Catalog: метаданные, lineage, data product ownership                         |
| Trino                       | **Assess** | Federated query engine поверх Lakehouse. Оцениваем как замену прямым SQL-запросам |
| Apache Spark                | **Assess** | Альтернатива Flink для batch-сценариев. Решение не принято                        |
| MS SQL Server 2008          | **Hold**   | End-of-life. Выводится по завершении миграции данных                              |
| On-premise серверы          | **Hold**   | Переход на облако. Новое оборудование не закупается                               |

| Docker          | **Adopt** | Упаковка и деплой всех сервисов                                                                                                                                  |

## Архитектурные паттерны

| Паттерн                         | Кольцо     | Обоснование                                                               |
|---------------------------------|------------|---------------------------------------------------------------------------|
| Event-Driven Architecture       | **Adopt**  | Основа межсервисной интеграции. Заменяет синхронный ESB                   |
| Domain-Driven Design            | **Adopt**  | Принцип разбиения на домены и bounded contexts                            |
| Database-per-domain             | **Adopt**  | Изоляция данных домена. Нет прямого доступа к чужим БД                    |
| Infrastructure as Code          | **Adopt**  | Terraform для всей инфраструктуры                                         |
| CI/CD pipelines                 | **Adopt**  | Автоматизированный деплой для всех доменов и платформы                    |
| Data Mesh                       | **Trial**  | Децентрализованное владение данными. Пилот на Clinical domain             |
| Self-service BI                 | **Trial**  | Аналитики строят отчёты самостоятельно без участия IT                     |
| Saga Pattern                    | **Trial**  | Компенсирующие транзакции для cross-domain бизнес-процессов               |
| CQRS                            | **Assess** | Command/Query разделение. Актуально для Fintech domain при росте нагрузки |
| Multi-region data residency     | **Assess** | Разделение хранилища по юрисдикциям при выходе в новые регионы            |
| Zero-trust security             | **Assess** | Оцениваем как модель для периметра безопасности при росте числа доменов   |
| Centralized ESB / Orchestration | **Hold**   | Заменяется событийной архитектурой. Новые интеграции только через Kafka   |
| Monolithic DWH / Batch-only ETL | **Hold**   | Заменяется Data Lakehouse + Flink streaming                               |
